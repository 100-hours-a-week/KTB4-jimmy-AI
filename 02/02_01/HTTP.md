# HTTP
 > HyperText Transfer Protocol — 웹에서 데이터를 주고받는 규칙

브라우저와 서버가 대화하는 방식을 정해놓은 프로토콜. TCP/IP 모델에서 응용 계층에 속함.

핵심 특징:

- **요청-응답 구조** — 클라이언트가 먼저 요청해야만 서버가 응답
- **무상태(Stateless)** — 각 요청은 독립적. 서버는 이전 요청을 기억하지 않음. 그래서 로그인 유지에 쿠키/세션/토큰이 필요
- **텍스트 기반** — 요청과 응답이 사람이 읽을 수 있는 텍스트 형식

	HTTP 버전 흐름
	
	| 버전       | 특징                           |
	| -------- | ---------------------------- |
	| HTTP/1.1 | 현재도 가장 많이 쓰임. 요청마다 연결 수립     |
	| HTTP/2   | 한 연결에서 여러 요청 동시 처리. 속도 개선    |
	| HTTP/3   | TCP 대신 QUIC(UDP 기반) 사용. 더 빠름 |


## 헤더와 바디
```python
사용자 → URL 입력 → DNS 조회 → TCP 연결 → TLS → "HTTP 요청"
→ [웹 서버 ←(WSGI)→ 앱 서버 ←(ORM)→ DB] → "HTTP 응답" → 브라우저 렌더링
```

HTTP request message (요청), HTTP response message (응답) 둘 다 헤더/바디로 구성. 헤더-바디 사이 구분은 빈 줄(두 번 띄기). 파싱할 때 헤더-바디를 스플릿하는 것으로 시작.

요청 구조:

```python
GET /search?q=python HTTP/1.1        ← 요청 라인 (메서드 + 경로 + 버전)
Host: naver.com                      ← 헤더
User-Agent: Chrome/120               ← 헤더
Accept: text/html                    ← 헤더
                                     ← 빈 줄 (헤더 끝)
(body — GET은 보통 없음)             ← 바디
```

응답 구조:

```python
HTTP/1.1 200 OK                      ← 상태 라인 (버전 + 상태코드)
Content-Type: text/html              ← 헤더
Content-Length: 1234                  ← 헤더
                                     ← 빈 줄
<html>...</html>                     ← 바디 (실제 데이터)
```

## HTTP 요청 메서드
```python
사용자 → URL 입력 → DNS 조회 → TCP 연결 → TLS → "HTTP 요청(GET/POST)"
→ [웹 서버 ←(WSGI)→ 앱 서버 ←(ORM)→ DB] → HTTP 응답 → 브라우저 렌더링
```

웹 서버에게 구체적인 작업을 명확하게 지시하기 위해, URL과 함께 메서드를 명시하여 서버에게 특정 작업을 요청.

|메서드|의미|바디|예시|
|---|---|---|---|
|GET|데이터 조회|❌|게시글 읽기|
|POST|데이터 생성|✅|회원가입, 글 작성|
|PUT|데이터 전체 수정|✅|프로필 전체 업데이트|
|PATCH|데이터 일부 수정|✅|닉네임만 변경|
|DELETE|데이터 삭제|❌|게시글 삭제|

## HTTP 상태 코드
```python
사용자 → URL 입력 → DNS 조회 → TCP 연결 → TLS → HTTP 요청
→ [웹 서버 ←(WSGI)→ 앱 서버 ←(ORM)→ DB] → "HTTP 응답(200/404/500)" → 브라우저 렌더링
```

서버가 응답할 때 "결과가 어땠는지" 알려주는 숫자.

|범위|의미|
|---|---|
|1xx|정보 메시지|
|2xx|성공|
|3xx|리다이렉션|
|4xx|클라이언트 오류|
|5xx|서버 오류|

### 빈출 코드

|상태 코드|설명|예시|
|---|---|---|
|200|요청이 성공적으로 처리됨|게시글 목록 조회, 상세조회, 업데이트|
|201|요청 성공 + 새로운 리소스 생성됨|게시글 추가|
|204|헤더는 유효하나, 보내줄 내용 없음|게시글 삭제|
|400|잘못된 문법으로 서버가 요청을 이해할 수 없음|제목이나 본문 데이터가 전달 안 된 경우|
|401|인증되지 않은 접근|로그인 없이 회원 전용 글을 읽으려 할 때|
|403|인가되지 않은 접근|일반 유저가 관리자 페이지에 접근하려 할 때|
|404|요청받은 리소스를 찾을 수 없음|삭제된 게시글을 조회하려 할 때|
|429|너무 많은 요청|잘못된 비밀번호로 많은 요청을 했을 때|
|500|서버가 처리 방법을 알 수 없음|서버에서 처리할 수 없는 오류 발생|
|503|서버가 요청을 처리할 준비가 되지 않음 (일시적 사용 불가)|서버에 트래픽이 몰리거나 유지보수 중|

## HTTP URL, DNS
```python
사용자 → "URL 입력" → "DNS 조회" → TCP 연결 → TLS → HTTP 요청
→ [웹 서버 ←(WSGI)→ 앱 서버 ←(ORM)→ DB] → HTTP 응답 → 브라우저 렌더링
```

> Uniform Resource Locator — 인터넷에서 자원의 위치를 나타내는 주소

```python
https://www.naver.com:443/search?q=python#결과
  ↑         ↑            ↑   ↑        ↑       ↑
프로토콜   도메인        포트 경로    쿼리    앵커
```

- Scheme(프로토콜) = 브라우저가 리소스를 요청할 때 사용하는 프로토콜 (http, https, ftp)
- 도메인 = 서버의 이름 (IP 주소 대신 쓰는 사람이 읽기 쉬운 주소)
- 포트 = 서버 안의 서비스 구분 번호 (http=80, https=443 기본값이라 생략 가능)
- 경로 = 서버 내의 리소스 위치

### DNS (Domain Name System)

> 도메인 이름을 IP 주소로 변환하는 시스템

네이버가 도메인 등록 업체(가비아, GoDaddy 등)에 돈 내고 도메인을 구매하고, DNS 서버에 IP 주소를 등록. 브라우저가 물어보면 DNS 계층 구조를 타고 IP를 알아옴.

```python
브라우저 → 로컬 DNS (통신사) → 루트 DNS → TLD DNS (.com) → 네이버 DNS → IP 반환
```

### 브라우저에 URL 입력 시 전체 흐름

```python
1.  브라우저가 URL 파싱 (프로토콜, 도메인, 포트, 경로)
2.  캐시 확인 (브라우저 캐시 → OS 캐시 → 라우터 캐시)
3.  DNS 조회 (도메인 → IP 주소 변환)
4.  TCP 연결 (3-way handshake: SYN → SYN-ACK → ACK)
5.  TLS handshake (HTTPS인 경우 — 인증서 검증, 암호화 키 교환)
6.  HTTP 요청 전송
7.  서버 처리 (웹 서버 → 앱 서버 → DB → HTML 생성)
8.  HTTP 응답 수신
9.  브라우저 렌더링 (HTML 파싱 → DOM → CSS → JS → 화면 표시)
10. 추가 리소스 요청 (이미지, CSS, JS 파일마다 HTTP 요청 반복)
```

## 경로 변수와 쿼리 스트링
```python
사용자 → "URL 입력(/posts/1?sort=date)" → DNS 조회 → TCP 연결 → TLS → HTTP 요청
→ [웹 서버 ←(WSGI)→ 앱 서버 ←(ORM)→ DB] → HTTP 응답 → 브라우저 렌더링
```

### Query string

클라이언트에서 서버에 추가 정보를 전달하기 위해 사용되는 문자열. URL 끝에 `?` 기호를 붙이고, 그 뒤에 `key=value` 형태로 데이터 전달.

```python
http://example.com/posts?category=books&search=coding
```

### Path variable

경로 내에 포함되어 있는, 특정 자원을 식별하는 변수.

```python
/posts/{id} → 실제 요청 시 /posts/100
```

## HTTPS와 TLS
```python
사용자 → URL 입력 → DNS 조회 → TCP 연결 → "TLS" → HTTP 요청
→ [웹 서버 ←(WSGI)→ 앱 서버 ←(ORM)→ DB] → HTTP 응답 → 브라우저 렌더링
```
TLS = 대화 내용을 암호화하는 기술
HTTP는 평문(텍스트) 전송이라 중간에 누가 가로채면 내용이 다 보임. HTTPS = HTTP + TLS 암호화 레이어.

```python
HTTP  : 브라우저 → (평문) → 서버
HTTPS : 브라우저 → (암호화) → 서버
```

주소창 자물쇠 아이콘이 TLS 연결이 됐다는 표시.
